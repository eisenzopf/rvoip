# RFC 3261 Transaction-Stateful Proxy Conformance

Status: **Partial; release qualification is pending.**

This matrix defines the bounded standards claim for
`rvoip-sip-proxy`. It covers the behavior of a transaction-stateful,
dialog-agnostic proxy under:

- [RFC 3261 sections 9, 16, and 17][rfc3261];
- [RFC 4320 section 4][rfc4320], which updates non-INVITE
  transactions; and
- [RFC 6026 sections 7 and 8][rfc6026], which correct INVITE 2xx and
  stray-response handling.

It is not a claim that every SIP extension is implemented, that every
`rvoip` SIP component is a proxy, or that Bridgefu is a proxy. Bridgefu
is a media-terminating B2BUA and does not use this crate for its normal
call bridging.

The source and worktree used for this effort are recorded in
[`CONFORMANCE_STATUS.md`](CONFORMANCE_STATUS.md).

## How to read the matrix

The status column describes the code and evidence available in the
current development worktree:

- **Candidate**: an implementation seam and a focused test exist, but
  the release evidence has not completed.
- **Delegated**: the behavior is owned by another pinned `rvoip`
  component, usually `rvoip-sip-dialog::TransactionManager`; its
  evidence must be included in the proxy release report.
- **Gap**: implementation or executable evidence is absent or known to
  be incomplete.
- **Policy boundary**: application policy supplies an input, but the
  proxy must still validate and process that input as described here.

No row in this document is a green conformance result by itself. A test
name means that source-level evidence exists; it does not mean that the
test passed against the eventual release revision. The final report
must attach the exact source revision, command, environment, result, and
artifacts.
